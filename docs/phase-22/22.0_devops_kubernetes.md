## STEP 22.3 — Autoscaling

**File:** `services/hpa.yaml`

### Horizontal Pod Autoscalers

| Service | Min | Max | CPU Target | Memory Target |
|---------|-----|-----|------------|---------------|
| backend-api | 2 | 10 | 70% | 80% |
| frontend | 2 | 6 | 70% | 80% |
| worker | 1 | 8 | 80% | 85% |
| ai-service | 1 | 4 | 75% | 80% |

### Scaling Behavior

**Scale Up:**
- backend-api: +2 pods per 60s (stabilization: 60s)
- frontend: +2 pods per 60s (stabilization: 60s)
- worker: +2 pods per 120s (stabilization: 120s)
- ai-service: +1 pod per 180s (stabilization: 180s)

**Scale Down:**
- All: -1 pod per 120-300s (stabilization: 300-600s)

### Metrics
- CPU utilization (primary)
- Memory utilization (secondary)

## CI/CD Pipeline

### GitHub Actions

**ci.yml:**
1. Lint frontend (next lint)
2. Lint backend (ruff check)
3. Test backend (pytest)
4. Build frontend (next build)
5. Build Docker images

**deploy.yml:**
1. Build Docker images
2. Push to ECR
3. Update ECS task definition
4. Deploy to ECS

## Disaster Recovery

### Backup Strategy
- PostgreSQL: pg_dump every 6 hours → S3
- Redis: BGSAVE every 1 hour → S3
- ClickHouse: Native backup daily → S3

### Failover
- Aurora: Automatic failover
- K8s: Pod rescheduling
- Route53: DNS failover
