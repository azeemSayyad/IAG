## STEP 17.1 — Slot Generation

**File:** `booking/services/slots.py`

Generates 15-minute appointment slots within business hours.

### Configuration
- Business hours: 10:00 AM - 9:00 PM
- Slot duration: 15 minutes
- Max days ahead: 3
- Slots per hour: 4

### Functions
- `generate_slots_for_date(date)` — Generate all slots for a date
- `generate_slots_for_range(start, end)` — Generate slots for date range
- `get_available_slots(date, booked_slots, locked_slots)` — Filter available slots
- `format_slot_options(slots, count=3)` — Format numbered options for SMS
- `parse_slot_selection(selection, slots)` — Parse customer reply

## STEP 17.3 — Slot Locking Algorithm

**File:** `booking/services/locking.py`

Distributed locking using Redis to prevent double-booking.

### Flow
```
Acquire Lock → Validate Slot → Book Appointment → Release Lock
```

### Functions
- `acquire_slot_lock(slot_key, lead_id, ttl=300)` — Acquire distributed lock
- `release_slot_lock(slot_key, lead_id)` — Release lock (only if owned)
- `is_slot_locked(slot_key)` — Check if slot is locked
- `get_slot_lock_info(slot_key)` — Get lock details
- `extend_slot_lock(slot_key, lead_id, ttl)` — Extend lock TTL

### Configuration
- Lock TTL: 300 seconds (5 minutes)
- Lock key format: `slot_lock:{tenant_id}:{date}:{time}`
- Ownership verification: Only lock holder can release

## STEP 17.4 — Weighted Round Robin Assignment

**File:** `booking/services/assignment.py`

Fair agent assignment using weighted scoring.

### Scoring Formula
```
agent_score = (weight_score * 0.6) + (capacity_score * 0.4)
```

Where:
- `weight_score` = agent.weight / 100 (default 100)
- `capacity_score` = 1.0 - (current_appointments / daily_capacity)

### Functions
- `get_available_agents_for_slot(tenant_id, slot_time, skills)` — Filter available agents
- `get_agent_workload(agent_id, date)` — Count appointments
- `calculate_agent_score(agent, date)` — Calculate assignment score
- `assign_agent(tenant_id, slot_time, skills)` — Select best agent

### Factors
- Agent weight (configurable priority)
- Daily capacity (default 8)
- Current utilization
- Required skills
- Schedule conflicts

## STEP 17.5 — Idle Gap Minimization

**File:** `booking/services/idle_optimizer.py`

AI-powered appointment clustering to reduce agent idle time.

### Strategy
1. Find gaps in agent schedules
2. Score slots based on clustering potential
3. Prefer slots adjacent to existing appointments
4. Avoid creating small unusable gaps (< 15 min)

### Functions
- `get_agent_schedule_gaps(agent_id, date)` — Find idle gaps
- `find_best_cluster_slot(agent_id, date, preferred_time)` — Find optimal slot
- `calculate_utilization_score(appointments, availability)` — Calculate utilization
- `suggest_slot_for_lead(tenant_id, preferred_time)` — Suggest best slot across agents

### Scoring
- Slots adjacent to existing appointments: 0 points (best)
- Slots creating gaps < 15 min: 100 points (worst)
- First appointment of day: 0 points

## STEP 17.6 — Overflow Handling

**File:** `booking/services/overflow.py`

Handles scenarios when no slots are available.

### Options
1. **Waitlist** — Notify when slot opens
2. **Nearest Alternative** — Find closest available time
3. **Overflow Queue** — Route to next available agent

### Functions
- `add_to_waitlist(tenant_id, lead_id, preferred_time)` — Add to waitlist
- `remove_from_waitlist(tenant_id, lead_id)` — Remove from waitlist
- `get_waitlist(tenant_id)` — Get all waitlist entries
- `check_waitlist_for_slot(tenant_id, agent_id, start, end)` — Check matches
- `find_nearest_alternative(tenant_id, preferred_time)` — Find closest slot
- `add_to_overflow_queue(tenant_id, lead_id, preferred_time)` — Add to overflow
- `process_overflow_queue(tenant_id)` — Process overflow queue

### API Endpoints
- `POST /booking/waitlist` — Add to waitlist
- `GET /booking/waitlist` — List waitlist
- `DELETE /booking/waitlist/{lead_id}` — Remove from waitlist
- `GET /booking/overflow` — List overflow queue

## STEP 17.7 — No-show Prediction

**File:** `booking/services/no_show_prediction.py`

Predicts probability of lead not showing up for appointment.

### Features Used
| Feature | Weight | Description |
|---------|--------|-------------|
| Lead Engagement | 20% | Message count and recency |
| Time Since Booking | 15% | Gap between booking and appointment |
| Time of Day | 10% | Business hours vs off-hours |
| Day of Week | 5% | Weekday vs weekend |
| Lead Source | 10% | Source reliability |
| No-show History | 15% | Previous no-show rate |
| Confirmation Status | 15% | Reminders sent |
| Reminder Response | 10% | Recent engagement |

### Risk Levels
- **Low** (< 20%): Standard reminders
- **Medium** (20-50%): Enhanced reminders
- **High** (50-80%): Call to confirm
- **Critical** (> 80%): Consider overbooking

### Functions
- `extract_no_show_features(db, appointment, lead)` — Extract prediction features
- `predict_no_show_probability(features)` — Calculate probability
- `predict_appointment_no_show(db, appointment_id)` — Predict for single appointment
- `predict_batch_no_shows(db, tenant_id, date)` — Predict for all appointments on date
- `get_risk_recommendations(risk_level, features)` — Get actionable recommendations

### API Endpoints
- `GET /booking/no-show/predict?appointment_id=...` — Predict for appointment
- `GET /booking/no-show/batch?date=2026-01-15` — Predict for date
