# Phase 15 — Database Layer Architecture

## Multi-Layer Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                      APPLICATION LAYER                          │
│  FastAPI + SQLAlchemy ORM                                       │
└─────────────────────┬───────────────────────────────────────────┘
                      │
┌─────────────────────▼───────────────────────────────────────────┐
│                    DATA ACCESS LAYER                            │
│  ┌──────────┐  ┌──────┐  ┌───────┐  ┌───────────┐  ┌────┐    │
│  │PostgreSQL│  │Redis │  │Qdrant │  │ClickHouse │  │ S3 │    │
│  └──────────┘  └──────┘  └───────┘  └───────────┘  └────┘    │
└─────────────────────────────────────────────────────────────────┘
```

## Layer Responsibilities

### PostgreSQL (Primary Relational DB)
- All transactional operations
- User/agent/lead management
- Appointment booking with ACID guarantees
- Campaign configuration
- RBAC and permissions
- Audit logging
- Row-level security for tenant isolation

### Redis (Cache + Realtime)
- Appointment slot locking (distributed locks)
- WebSocket pub/sub for realtime updates
- Background job queues (outbound_sms, retries, reminders, followups)
- API response caching
- Rate limiting counters
- Session acceleration
- Retry timers and delayed jobs

### Qdrant (Vector Memory DB)
- Conversation embeddings for semantic search
- AI long-term memory
- Objection history embeddings
- AI summary storage
- Lead similarity search

### ClickHouse (Analytics DB)
- Large-scale event analytics
- Campaign performance reporting
- Agent utilization analytics
- Historical trend analysis
- ML feature aggregation
- Time-series data

### AWS S3 (Object Storage)
- CSV import files
- Export files (CSV, PDF)
- Backup storage
- Static assets
