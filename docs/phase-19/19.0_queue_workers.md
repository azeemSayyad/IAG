## STEP 19.1 — Queue Types

**File:** `app/core/queues.py`

Redis-based job queues for async processing.

| Queue | Purpose | Priority |
|-------|---------|----------|
| queue:outbound_sms | SMS sending jobs | High |
| queue:retries | Failed job retries | Normal |
| queue:reminders | Appointment reminders | High |
| queue:ai_generation | AI response generation | Normal |
| queue:analytics | Analytics processing | Low |
| queue:followups | Follow-up sequences | Normal |
| queue:ingestion | Lead import processing | Normal |
| queue:dead_letter | Failed jobs (DLQ) | — |

### Job Structure
```python
Job:
    job_id: UUID
    job_type: str
    payload: Dict
    queue: QueueType
    priority: JobPriority (0-3)
    max_retries: int (default 3)
    delay_seconds: int
    idempotency_key: str
    status: JobStatus
    attempts: int
    last_error: str
    created_at: datetime
    processed_at: datetime
    next_retry_at: datetime
```

### QueueManager Functions
- `enqueue(job_type, payload, queue, priority, max_retries, delay_seconds)` — Add job
- `dequeue(queue, timeout)` — Get next job
- `complete_job(job)` — Mark completed
- `fail_job(job, error)` — Mark failed (retry or DLQ)
- `get_queue_stats()` — Get all queue statistics
- `process_delayed_jobs()` — Move delayed jobs to ready
- `retry_dlq_job(job_id)` — Retry dead-lettered job

## STEP 19.3 — Retry Strategy

**Exponential Backoff**

```
Attempt 1: 60 seconds (1 min)
Attempt 2: 120 seconds (2 min)
Attempt 3: 240 seconds (4 min)
Attempt 4: 480 seconds (8 min)
Attempt 5: 960 seconds (16 min)
...
Max: 3600 seconds (1 hour)
```

Formula: `delay = base_delay * 2^(attempt-1)`
- Base delay: 60 seconds
- Max delay: 3600 seconds (1 hour)

### Configuration per Task
```python
@celery_app.task(
    max_retries=3,
    default_retry_delay=60,
    retry_backoff=True,
    retry_backoff_max=3600,
)
```

## STEP 19.4 — Idempotency

**Prevents duplicate jobs using idempotency keys.**

### Key Generation
```python
idempotency_key = f"{job_type}:{json.dumps(payload, sort_keys=True)}"
```

### Storage
- Redis key: `idempotency:{key}`
- TTL: 24 hours
- Value: job_id and creation timestamp

### Check Flow
1. Generate idempotency key from job type + payload
2. Check if key exists in Redis
3. If exists, skip enqueue (return None)
4. If not exists, enqueue job and mark key

## STEP 19.5 — Dead Letter Queues

**Failed jobs move to DLQ after max retries.**

### DLQ Features
- Redis list: `queue:dead_letter`
- Job TTL: 30 days (vs 7 days for active jobs)
- Manual retry via API or admin
- Monitoring via queue stats

### DLQ Flow
```
Job fails → Check retries remaining
  ├── Yes → Schedule retry with backoff
  └── No → Move to DLQ
```

### Retry from DLQ
```python
queue_manager.retry_dlq_job(job_id)
```

## STEP 19.6 — Worker Scaling

**Scale workers based on queue metrics.**

### Metrics Tracked
- Queue size (pending jobs)
- Delayed jobs count
- Processing rate (jobs/minute)
- Error rate
- DLQ size

### Scaling Rules
| Metric | Threshold | Action |
|--------|-----------|--------|
| Queue size > 100 | Scale up | Add workers |
| Queue size < 10 | Scale down | Remove workers |
| Error rate > 20% | Alert | Investigate |
| DLQ size > 50 | Alert | Manual review |

### Queue Statistics
