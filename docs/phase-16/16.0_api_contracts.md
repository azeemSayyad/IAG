# Phase 16 — API Contract Design

## API Standards (Step 16.1)

- REST APIs for CRUD operations
- WebSockets for realtime updates (Socket.IO)
- Internal events for async workflows (Redis pub/sub)

## API Versioning (Step 16.2)

All endpoints are under `/api/v1/` prefix.

Internal AI endpoints are under `/api/v1/internal/`.

---

## Authentication APIs (Step 16.3)

### Register
```
POST /api/v1/auth/register
Body: { email, password, first_name, last_name, company_name }
Response: { access_token, refresh_token, user }
```

### Login
```
POST /api/v1/auth/login
Body: { email, password }
Response: { access_token, refresh_token, user }
```

### Refresh Token
```
POST /api/v1/auth/refresh
Body: { refresh_token }
Response: { access_token, refresh_token }
```

### Get Current User
```
GET /api/v1/auth/me
Response: { id, email, role, tenant_id, ... }
```

### Change Password
```
POST /api/v1/auth/change-password
Body: { current_password, new_password }
Response: { message }
```

### Password Reset
```
POST /api/v1/auth/password-reset-request
Body: { email }
Response: { message }

POST /api/v1/auth/password-reset-confirm
Body: { token, new_password }
Response: { message }
```

### Logout
```
POST /api/v1/auth/logout
Response: { message }
```

## Lead APIs (Step 16.4)

```

### Update Lead
```

## API Validation (Step 16.9)

All request bodies use Pydantic models for validation:
- Type checking
- Required field validation
- Format validation (email, phone, UUID)
- Range validation (lead_score 0-100)
- Enum validation (status, role, disposition)

## API Rate Limiting (Step 16.10)

Redis-based rate limiting with sliding window:
- Login: 5 per 5 minutes
- Register: 3 per hour
- API General: 100 per minute
- SMS Send: 10 per minute
- CSV Import: 10 per hour
