# Step 0.2 — Define User Roles

## Role Hierarchy

```
Super Admin
  └── Company Admin (Tenant Admin)
        └── Manager
              └── Agent

AI System — autonomous, operates alongside all roles
```

---

## Role 1: Super Admin

### Who
Platform owner / SaaS operator. Controls the entire multi-tenant platform.

### Permissions

| Area | Access |
|------|--------|
| Tenants | Create, suspend, delete, configure |
| Billing | Manage plans, invoices, payments |
| Platform Settings | Global configuration, feature flags |
| Infrastructure | Monitoring, scaling, deployments |
| All Tenant Data | Read-only audit access across all tenants |
| User Management | Can impersonate any user for support |

### Key Actions

- Onboard new company tenants
- Configure subscription plans (Starter, Growth, Enterprise)
- Monitor platform health and usage
- Manage global AI model configurations
- Handle escalations from tenant admins

---

## Role 2: Company Admin (Tenant Admin)

### Who
Business owner or operations manager for a single tenant/company.

### Permissions

| Area | Access |
|------|--------|
| Agents | Create, edit, deactivate, assign shifts |
| Campaigns | Create, edit, pause, delete |
| Prompts | Configure AI prompts and tones |
| Analytics | Full dashboard access for their tenant |
| Scheduling | Set business hours, holidays, capacity |
| Billing | View their plan usage |
| Leads | View all leads, export data |
| Conversations | View all AI conversations |

### Key Actions

- Set up campaigns and AI messaging
- Configure booking rules (slot duration, hours, capacity)
- Monitor agent utilization and KPIs
- Review AI conversation quality
- Manage agent schedules and assignments

---

## Role 3: Manager (Optional)

### Who
Team lead or supervisor managing a group of agents.

### Permissions

| Area | Access |
|------|--------|
| Assigned Agents | View schedules, performance, notes |
| Assigned Leads | View and reassign |
| Analytics | Team-level dashboard |
| Appointments | View team calendar, reassign calls |

### Key Actions

- Monitor team performance
- Reassign appointments when agents are unavailable
- Review call dispositions
- Escalate issues to Company Admin

---

## Role 4: Agent

### Who
Call center agent who handles appointments and closes deals.

### Permissions

| Area | Access |
|------|--------|
| Appointments | View own schedule, update status |
| Lead Details | View assigned lead history and AI summary |
| Notes | Add call notes and dispositions |
| Calendar | View own daily/weekly agenda |
| Availability | Set own breaks and availability |

### Key Actions

- View upcoming calls with AI-generated lead summaries
- Complete calls and update disposition (won/lost/follow-up/no-answer)
- Write notes about the conversation
- Mark availability for scheduling

---

## Role 5: AI System

### Who
Automated AI agents that operate autonomously across the platform.

### Permissions

| Area | Access |
|------|--------|
| Leads | Read lead data, update lead scores |
| Conversations | Send/receive messages |
| Appointments | Create, confirm, reschedule, cancel |
| Scheduling | Read availability, lock slots |
| Campaigns | Execute campaign workflows |
| Analytics | Write metrics and events |

### Key Actions

- Send outreach SMS to new leads
- Detect customer intent from replies
- Push booking slots when customer is interested
- Book appointments and assign agents
- Send reminders (24h, 1h, 15m)
- Follow up on no-replies and no-shows
- Log all actions for audit trail

---

## Authentication & Authorization

### JWT Token Structure

```json
{
  "sub": "user_id",
  "tenant_id": "tenant_id",
  "role": "super_admin | tenant_admin | manager | agent",
  "permissions": ["leads.read", "appointments.write", ...],
  "exp": 1716000000
}
```

### Access Control Rules

1. Every API request must include a valid JWT
2. Every database query must filter by `tenant_id` from the token
3. Role-based middleware checks permissions before handler execution
4. AI system uses service-to-service authentication (API keys)
5. Impersonation requires super_admin role and audit logging

---

## Multi-Tenancy Isolation

- All data scoped by `tenant_id`
- No cross-tenant data access
- Shared infrastructure, isolated data
- Tenant-level feature flags and configuration
