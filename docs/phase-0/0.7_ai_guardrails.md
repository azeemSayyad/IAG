# Step 0.7 — AI Guardrails

## Purpose

AI guardrails ensure the AI system operates safely, legally, and on-brand. Every AI-generated message passes through a validation layer before reaching a customer.

---

## Rules: What AI Must NEVER Do

### 1. Never Hallucinate Pricing

- AI must never invent, guess, or fabricate pricing
- If pricing is needed, AI must use data from the `campaigns` or `products` table
- If no pricing data exists, AI must say: "I'll have an agent go over pricing with you"

**Validation:**
```
If response contains dollar amounts ($, price, cost, rate, premium):
    → Verify against campaign.product_pricing
    → If not found → replace with fallback response
```

### 2. Never Violate Compliance

- Never send messages outside allowed hours (8 AM - 9 PM recipient timezone)
- Never continue messaging after opt-out
- Never share one customer's data with another
- Never make medical or legal claims
- Never guarantee coverage or approval

**Validation:**
```
Before every send:
    → Check TCPA opt-out status
    → Check recipient timezone business hours
    → Scan for prohibited claims
    → Verify consent exists
```

### 3. Never Spam Users

- Maximum 3 outreach attempts per lead per campaign
- Minimum 24 hours between messages
- Maximum 1 message per conversation turn
- Stop all messaging after STOP intent detected

**Validation:**
```
Before sending:
    → Count messages to this lead in last 72 hours
    → Check time since last message
    → Verify no STOP intent in conversation history
```

### 4. Never Give Fake Promises

- Never promise specific outcomes ("You will be approved")
- Never guarantee savings amounts
- Never claim to be a human
- Never make time-pressure claims that are false ("This offer expires today" when it doesn't)

**Validation:**
```
Scan response for:
    → Guarantee language (guarantee, promise, definitely, 100%)
    → False urgency (expires today, last chance) without campaign deadline
    → Human identity claims (I'm, my name is, as a person)
```

## Prompt Templates

### Template Structure

Every AI prompt follows this structure:

```
SYSTEM PROMPT:
  - Role definition
  - Guardrail rules
  - Output format

CONTEXT:
  - Lead data
  - Conversation history
  - Campaign settings
  - Memory (objections, preferences)

TASK:
  - Current intent
  - Desired action
  - Constraints

OUTPUT:
  - Response text only
  - No explanations
  - No metadata
```

### Example: Outreach Template

```
SYSTEM:
You are a friendly insurance assistant. You help customers learn about
insurance options and book appointments with licensed agents.

RULES:
- Never invent pricing or guarantees
- Never claim to be human
- Keep messages under 160 characters when possible
- Be warm but professional
- If asked about pricing, say you'll connect them with an agent

CONTEXT:
Customer: {first_name}
Source: {source}
Campaign: {campaign_name}
Prior messages: {conversation_history}
Known objections: {objections}

TASK:
Send an initial outreach message. Introduce yourself as an AI assistant
and offer to help them explore insurance options. End with a question
to encourage a reply.

OUTPUT:
[Message text only]
```

### Example: Objection Handling Template

```
SYSTEM:
You handle customer objections about insurance. Be empathetic and factual.

RULES:
- Acknowledge the concern first
- Provide factual information only
- Never dismiss their concern
- Redirect to booking after addressing
- If you can't answer, offer to connect with an agent

CONTEXT:
Customer: {first_name}
Objection: {objection_text}
Conversation history: {conversation_history}

TASK:
Address this objection empathetically. Then gently redirect toward
booking an appointment with an agent who can provide more details.

OUTPUT:
[Message text only]
```

## Validation Layer

### Pre-Send Validation Pipeline

Every AI-generated message passes through this pipeline before being sent:

```
AI Generates Response
        ↓
    Layer 1: Length Check
    - SMS max 1600 characters
    - Prefer under 160 characters
    - If too long → truncate or regenerate
        ↓
    Layer 2: Prohibited Content Scan
    - Pricing hallucination check
    - False guarantee check
    - Compliance claim check
    - Identity claim check
        ↓
    Layer 3: TCPA Compliance Check
    - Opt-out status verified
    - Business hours check
    - Message frequency check
        ↓
    Layer 4: Tone Check
    - Not too aggressive
    - Not too casual (unless campaign setting)
    - No ALL CAPS
    - No excessive punctuation (!!!)
        ↓
    Layer 5: Final Approval
    - Pass → send via Engage Clouds
    - Fail → use fallback response
    - Uncertain → escalate to human review queue
```

### Validation Rules Table

| Rule | Check | Action on Fail |
|------|-------|----------------|
| No hallucinated pricing | Regex + keyword scan | Replace with fallback |
| No false guarantees | Keyword scan | Replace with fallback |
| No human identity claims | Keyword scan | Replace with fallback |
| Under 1600 chars | Length check | Truncate with ellipsis |
| TCPA compliant | DB check | Block send, log violation |
| Business hours | Timezone check | Queue for next valid window |
| Frequency limit | Count query | Block send, log violation |
| No profanity | Keyword scan | Replace with fallback |

## Fallback Responses

When the AI fails validation or cannot generate an appropriate response:

### Fallback by Situation

| Situation | Fallback Response |
|-----------|------------------|
| Pricing question (no data) | "Great question! Let me connect you with an agent who can give you exact numbers." |
| Complex question (AI unsure) | "That's a great question. Let me get you connected with one of our specialists." |
| Compliance concern | "I want to make sure you get accurate info. Let me have an agent reach out." |
| Validation failure | "Thanks for your message! One of our team members will follow up shortly." |
| AI timeout/error | "Sorry for the delay! We'll get back to you right away." |
| Unrecognized message | "Thanks for reaching out! Would you like to learn more about our insurance options?" |

### Fallback Selection Logic

```
Validation Failed?
    ↓
Identify failure type
    ↓
Select appropriate fallback template
    ↓
Inject customer name if available
    ↓
Send fallback message
    ↓
Flag conversation for human review
    ↓
Log the failure for AI improvement
```

## Escalation Rules

### When to Escalate to Human

| Condition | Escalation Action |
|-----------|------------------|
| Customer requests to speak to human | Immediately pause AI, notify agent |
| Customer threatens legal action | Pause AI, alert admin |
| AI confidence below 0.5 for 3+ messages | Flag for human review |
| Customer sends 5+ messages without resolution | Auto-assign to agent |
| Sensitive topic detected (death, illness, claim) | Route to senior agent |
| AI fails validation 3 times in a row | Pause conversation, alert admin |

### Escalation Workflow

```
Escalation Triggered
        ↓
    Update conversation status = "paused"
        ↓
    Notify assigned agent (or find available agent)
        ↓
    Send customer holding message
    - "Let me connect you with a team member who can help."
        ↓
    Agent receives notification with:
    - Full conversation history
    - AI summary of situation
    - Detected objections
    - Recommended next steps
        ↓
    Agent takes over conversation
        ↓
    AI resumes only when agent explicitly hands back
```

## Monitoring & Alerts

### Real-Time Monitoring

| Metric | Threshold | Alert |
|--------|-----------|-------|
| AI failure rate | > 10% of messages | Slack notification to admin |
| Validation failure rate | > 5% of messages | Email to ops team |
| Escalation rate | > 15% of conversations | Dashboard alert |
| Average response time | > 5 seconds | Performance alert |
| TCPA violation | Any | Immediate alert + auto-pause |

### Weekly Review

- Review all escalated conversations
- Analyze AI failure patterns
- Update prompt templates based on failures
- Retrain intent classifier if accuracy drops
- Update guardrail rules for new edge cases
