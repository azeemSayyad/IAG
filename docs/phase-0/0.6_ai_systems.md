## Module 1: Outreach AI

### Purpose
Compose and send personalized SMS messages to leads.

### Inputs
- Lead data (name, source, state, history)
- Campaign configuration (tone, prompts, timing)
- Prior conversation history (if re-engaging)
- AI guardrails

### Outputs
- Personalized SMS message text
- Send timestamp

### How It Works

```
Lead Created
      ↓
Select Prompt Template (based on campaign)
      ↓
Inject Variables
  - {first_name}
  - {source}
  - {campaign_context}
  - {personalization_hooks}
      ↓
Apply Tone Settings
  - friendly, professional, urgent, casual
      ↓
Validate Against Guardrails
  - No hallucinated pricing
  - No false promises
  - TCPA compliant
      ↓
Send via Engage Clouds
      ↓
Log to messages table
```

### Key Features
- Dynamic prompt variables per lead
- Tone variation to avoid robotic feel
- A/B testing support for prompt variants
- Rate limiting to prevent carrier blocks
- Delivery status tracking

## Module 2: Intent Detection AI

### Purpose
Classify customer reply intent to determine next workflow action.

### Inputs
- Incoming SMS message text
- Conversation history (last 10 messages)
- Lead context (objections, sentiment history)

### Outputs
- Intent class (one of 8 categories)
- Confidence score (0-1)
- Detected entities (dates, times, product mentions)

### Intent Classes

| Intent | Description | Next Action |
|--------|-------------|-------------|
| POSITIVE | Customer is ready or eager | Push booking slots |
| INTERESTED | Customer wants more info | Answer, then push booking |
| SKEPTICAL | Customer has objections | Handle objection, then push booking |
| NEGATIVE | Customer is not interested | Acknowledge, offer value, soft close |
| STOP | Customer wants to opt out | Opt out immediately, update lead status |
| BOOK_NOW | Customer explicitly wants to book | Go directly to booking flow |
| QUESTION | Customer asked a specific question | Answer accurately, then push booking |
| RESCHEDULE | Customer wants to change existing booking | Go to reschedule flow |

### Architecture: Hybrid Approach

```
Incoming Message
      ↓
Fast Classifier (< 100ms)
  - Keyword matching
  - Regex patterns
  - Simple ML model (logistic regression)
  - Handles 80% of clear messages
      ↓
  High Confidence (> 0.85)?
      ↓ Yes → Return intent directly
      ↓ No
LLM Reasoning Layer
  - Full conversation context
  - Nuanced understanding
  - Handles sarcasm, ambiguity, slang
  - Returns intent + reasoning
```

### Why Hybrid
- Fast classifier handles obvious cases cheaply and quickly
- LLM handles edge cases that need reasoning
- Keeps costs down while maintaining accuracy
- LLM fallback ensures no message is misclassified

## Module 3: Scheduling AI

### Purpose
Manage appointment slots, present options, and book appointments.

### Inputs
- Agent availability (from agent_availability table)
- Existing appointments (booked slots)
- Customer preferences (if stated)
- Business rules (hours, slot duration, capacity)

### Outputs
- List of available slot options (3 numbered choices)
- Booking confirmation details
- Agent assignment

### How It Works

```
Booking Intent Detected
      ↓
Fetch Available Slots
  - Query agent_availability WHERE status = 'available'
  - Filter by business hours (10 AM - 9 PM)
  - Filter out already-booked slots
  - Look ahead up to 3 days
  - Apply 15-minute slot duration
      ↓
Rank Slots
  - Prefer sooner slots
  - Prefer slots with higher-rated agents
  - Balance across agents (weighted round robin)
      ↓
Present 3 Options
  - Format: "1. 11:15 AM  2. 11:30 AM  3. 11:45 AM"
      ↓
Customer Selects (by number)
      ↓
Validate Selection
  - Number in valid range?
  - Slot still available?
      ↓
Lock Slot (Redis/PostgreSQL)
  - Prevent double-booking
  - 5-minute lock TTL
      ↓
Assign Agent (Weighted Round Robin)
  - Check daily_capacity
  - Check concurrent limit
  - Select agent with highest weight that has capacity
      ↓
Create Appointment
  - Insert into appointments table
  - Update agent_availability status
      ↓
Send Confirmation
  - SMS to customer
  - Notification to agent
```

### Slot Rules
- 15-minute slots
- 4 appointments per hour per agent
- Book up to 3 days ahead
- No double-booking under any circumstances
- Lock expires in 5 minutes if not confirmed

## Module 4: Lead Scoring ML

### Purpose
Predict booking and conversion likelihood for each lead.

### Inputs

| Feature | Type | Source |
|---------|------|--------|
| Lead source | Categorical | CSV/webhook data |
| State | Categorical | Lead profile |
| Time of arrival | Temporal | Created timestamp |
| Prior engagement | Boolean | Conversation history |
| Response time | Numeric | Time to first reply |
| Message count | Numeric | Conversation table |
| Sentiment trend | Numeric | Sentiment history |
| Email present | Boolean | Lead profile |
| Phone valid | Boolean | Validation result |

### Outputs

| Output | Range | Description |
|--------|-------|-------------|
| booking_probability | 0-100 | Likelihood of booking an appointment |
| conversion_probability | 0-100 | Likelihood of closing a policy |
| lead_score | 0-100 | Composite score used for prioritization |

### Scoring Formula (Initial)

```
lead_score = (
    source_weight * 0.25 +
    response_score * 0.25 +
    engagement_score * 0.30 +
    completeness_score * 0.20
) * 100
```

### Score Tiers

| Score | Tier | Priority |
|-------|------|----------|
| 80-100 | Hot | Immediate outreach, best agents |
| 60-79 | Warm | Standard outreach |
| 40-59 | Cool | Slower cadence |
| 0-39 | Cold | Nurture campaign |

## Module 5: Follow-Up AI

### Purpose
Automate follow-up sequences for no-replies, no-shows, and post-call workflows.

### Inputs
- Lead status and timestamps
- Conversation history
- Appointment outcomes (disposition)
- Campaign follow-up rules

### Outputs
- Follow-up message text
- Scheduled send time
- Workflow state transitions

### Follow-Up Sequences

#### No Reply Sequence

```
Trigger: No reply within 24 hours of last outreach

Retry 1 (24h): Different opener
  - "Hey {name}, just checking in..."

Retry 2 (48h): Social proof angle
  - "We've helped hundreds of families save..."

Retry 3 (72h): Final attempt
  - "Last chance to lock in your rate..."

Move to Nurture (after 3 retries)
```

#### No-Show Sequence

```
Trigger: Appointment marked as no_show

Immediate (30min): Gentle follow-up
  - "We missed you today! Want to reschedule?"

Retry (24h): Value reinforcement
  - "Your spot is still available..."

Move to Nurture (if no response)
```

#### Post-Call Sequence

```
Trigger: Disposition = follow_up

Follow-up 1 (24h): Recap
  - "Great speaking with you! Here's what we discussed..."

Follow-up 2 (3 days): Check-in
  - "Any questions about what we covered?"

Follow-up 3 (7 days): Urgency
  - "Rates are changing soon..."
```

## Module 6: Analytics AI

### Purpose
Analyze platform data to surface insights and optimize performance.

### Inputs
- All appointment data
- All conversation data
- All lead data
- Campaign performance data
- Agent performance data

### Outputs

#### Prompt Optimization
- Which message templates get the highest reply rates
- Which tones work best for each lead source
- Which objection handling approaches convert best

#### Timing Optimization
- Best time of day to send outreach (by source, state)
- Best day of week for appointments
- Optimal follow-up intervals

#### Agent Performance Insights
- Which agents convert best
- Optimal agent scheduling patterns
- Capacity utilization patterns

#### Lead Pattern Analysis
- Highest-converting lead sources
- Geographic conversion patterns
- Seasonal trends

### How It Works

```
Daily Batch Job (2 AM)
      ↓
Aggregate Metrics
  - Reply rates by prompt variant
  - Booking rates by time slot
  - Conversion rates by agent
  - No-show patterns
      ↓
Run Analysis
  - Statistical significance testing
  - Trend detection
  - Anomaly detection
      ↓
Generate Recommendations
  - Prompt changes
  - Schedule adjustments
  - Campaign tweaks
      ↓
Surface to Admin Dashboard
```
