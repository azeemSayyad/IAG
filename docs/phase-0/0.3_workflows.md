# Step 0.3 — Define Workflows

## Workflow 1: Lead Flow

### Flow Diagram

```
Lead Arrives (CSV / Webhook / API)
        ↓
    Validate
    - Required fields present?
    - Email format valid?
    - Phone format valid?
        ↓
    Deduplicate
    - Check phone against existing leads
    - Check email against existing leads
    - If duplicate → merge or skip
        ↓
    Lead Score
    - Source quality (organic vs paid vs cold)
    - State/geography
    - Timing (business hours vs off-hours)
    - Prior engagement history
        ↓
    Store in Database
    - Insert into leads table
    - Set status = "new"
    - Set created_at = now()
        ↓
    Assign Campaign
    - Match lead to campaign by source/product/region
    - If no match → assign to default campaign
        ↓
    Trigger AI Outreach
    - Enqueue outbound SMS job
    - AI selects prompt template
    - AI personalizes message
    - Send via Engage Clouds
```

### Lead States

```
new → contacted → replied → qualified → booked → completed
                      ↓          ↓
                   unqualified  no_show → rebook
                      ↓
                   nurture
```

### Triggers at Each State

| State | Trigger |
|-------|---------|
| new | Auto-assign campaign, start outreach |
| contacted | Start no-reply timer (24h) |
| replied | Run intent detection |
| qualified | Push booking slots |
| booked | Assign agent, send confirmation |
| completed | Trigger disposition workflow |
| no_show | Trigger rebook flow |
| nurture | Add to long-term drip campaign |

## Workflow 2: AI Conversation Flow

### Flow Diagram

```
SMS Sent to Lead
        ↓
    Customer Replies (inbound SMS webhook)
        ↓
    Clean Message
    - Strip whitespace
    - Normalize text
    - Handle emojis
        ↓
    Retrieve Memory
    - Past objections
    - Past sentiment
    - Conversation history
    - Lead preferences
        ↓
    Intent Detection
    - POSITIVE → push for booking
    - INTERESTED → provide info, then push booking
    - SKEPTICAL → handle objection, then push booking
    - NEGATIVE → acknowledge, offer value
    - STOP → opt-out immediately
    - BOOK_NOW → go directly to booking flow
    - QUESTION → answer, then push booking
    - RESCHEDULE → go to reschedule flow
        ↓
    Generate AI Response
    - Select prompt template based on intent
    - Inject memory context
    - Apply tone settings
    - Apply guardrails
        ↓
    Send Response via Engage Clouds
        ↓
    Log Everything
    - Store message in messages table
    - Update conversation intent
    - Update lead score
    - Track timing metrics
```

### Conversation States

```
initiated → active → booking → booked → closed
                 ↓
              paused → resumed
                 ↓
              stopped (opt-out)
```

### Memory Context Per Conversation

- Customer name
- Source of lead
- All prior messages (last 10 for prompt, full history in DB)
- Detected objections
- Sentiment trend
- Preferred contact times
- Any stated preferences

## Workflow 3: Booking Flow

### Flow Diagram

```
AI Detects BOOK_NOW or POSITIVE Intent
        ↓
    Fetch Available Slots
    - Query agent_availability table
    - Filter out booked slots
    - Apply business hours (10 AM - 9 PM)
    - Apply 15-minute slot duration
    - Look ahead up to 3 days
        ↓
    Present Slots to Customer
    - Show 3 numbered options
    - Example: "1. 11:15 AM  2. 11:30 AM  3. 11:45 AM"
        ↓
    Customer Replies with Number
        ↓
    Validate Selection
    - Number in range?
    - Slot still available?
        ↓
    Lock Slot (Redis distributed lock or PostgreSQL row lock)
    - Prevent double-booking
    - Lock expires in 5 minutes if not confirmed
        ↓
    Assign Agent (Weighted Round Robin)
    - Check agent capacity
    - Check agent schedule
    - Assign based on weighted distribution
        ↓
    Create Appointment
    - Insert into appointments table
    - Set status = "confirmed"
    - Link lead_id and agent_id
        ↓
    Send Confirmation
    - SMS to customer with date/time/agent name
    - Notification to agent dashboard
    - Update agent calendar
        ↓
    Schedule Reminders
    - 24 hours before → SMS reminder
    - 1 hour before → SMS reminder
    - 15 minutes before → SMS reminder
```

### Slot Locking Rules

- Lock acquired via Redis SETNX or PostgreSQL `SELECT ... FOR UPDATE`
- Lock TTL: 5 minutes
- If customer doesn't confirm within 5 minutes → release lock
- If slot conflict detected → offer next available slot
- Never allow double-booking under any circumstances

### Booking States

```
pending → confirmed → completed
    ↓         ↓
 cancelled   no_show → rescheduled
```

### Post-Booking Triggers

| Event | Action |
|-------|--------|
| Appointment created | Notify agent, update calendar |
| 24h before | Send reminder SMS |
| 1h before | Send reminder SMS |
| 15m before | Send reminder SMS |
| Appointment completed | Trigger disposition |
| Customer cancels | Free slot, trigger follow-up |
| No-show | Trigger rebook flow |

## Workflow 4: Follow-Up Flow (No Reply)

```
No Reply Within 24 Hours
        ↓
    Retry #1 — Different Tone
    - Change opener
    - Add urgency or value prop
        ↓
    Still No Reply (48 hours)
        ↓
    Retry #2 — Different Angle
    - Social proof
    - Limited availability
        ↓
    Still No Reply (72 hours)
        ↓
    Retry #3 — Final Attempt
    - Direct ask
    - Last chance framing
        ↓
    Still No Reply
        ↓
    Move to Nurture Campaign
    - Long-term drip (weekly/monthly)
    - Re-engagement on trigger events
```

## Workflow 5: Missed Appointment Flow

```
Appointment Marked as No-Show
        ↓
    Wait 30 Minutes
        ↓
    AI Sends Follow-up SMS
    - "Hey {name}, we missed you! Want to reschedule?"
        ↓
    Customer Replies?
        ↓
    Yes → Offer 3 New Slots → Booking Flow
        ↓
    No Reply Within 24 Hours
        ↓
    Retry Follow-up
        ↓
    Still No Reply
        ↓
    Move to Nurture Campaign
```
