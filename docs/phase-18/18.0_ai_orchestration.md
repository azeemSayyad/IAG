## STEP 18.3 — Conversation State Machine

**File:** `ai/services/state_machine.py`

### States
| State | Description | Timeout |
|-------|-------------|---------|
| NEW_LEAD | Just created | — |
| OUTREACH | Initial message sent | 48h |
| WAITING_REPLY | Awaiting customer response | 72h |
| INTERESTED | Customer showed interest | 48h |
| SKEPTICAL | Customer has concerns | 48h |
| BOOKING | Slot selection in progress | 24h |
| BOOKED | Appointment confirmed | — |
| FOLLOW_UP | Post-appointment follow-up | 72h |
| NURTURE | Long-term nurture | — |
| STOPPED | Customer opted out | — |
| CLOSED | Conversation ended | — |

### State Transitions
```
NEW_LEAD → OUTREACH → WAITING_REPLY → INTERESTED → BOOKING → BOOKED → FOLLOW_UP
                      ↓                 ↓             ↓
                    SKEPTICAL → INTERESTED         NURTURE
                      ↓
                    STOPPED
```

### Events
- `lead_created`, `outreach_sent`, `customer_replied`
- `intent_positive`, `intent_interested`, `intent_skeptical`
- `intent_negative`, `intent_stop`, `intent_book_now`
- `intent_question`, `intent_reschedule`
- `booking_started`, `slot_selected`, `appointment_booked`
- `appointment_cancelled`, `appointment_completed`, `disposition_set`
- `no_reply`, `timeout`, `manual_override`

### Entry Actions
Each state triggers specific actions on entry:
- OUTREACH → send_initial_outreach
- BOOKING → show_available_slots
- BOOKED → send_confirmation, schedule_reminders
- NURTURE → add_to_nurture_campaign

## STEP 18.5 — Hallucination Prevention

**File:** `ai/services/hallucination_guard.py`

### Validation Pipeline
1. **Length Check** — Response must be 10-1600 characters
2. **Prohibited Content Scan** — No medical/legal advice, false guarantees, false urgency
3. **Pricing Validation** — Only use campaign-provided pricing
4. **Compliance Check** — No medical/legal claims, no guarantees
5. **Tone Check** — Appropriate for context, no aggressive language

### Prohibited Patterns
- Medical advice (cure, treat, diagnose)
- Legal advice (legal advice, sue, lawsuit)
- False guarantees (guaranteed, 100% sure, promise)
- False urgency (last chance, only X left, expire today)
- Competitor bashing
- PII leaks (SSN, credit card)

### Safe Fallbacks
When validation fails, returns pre-approved compliant responses.

## STEP 18.6 — Token Optimization

**File:** `ai/services/token_optimizer.py`

### Strategies

#### 1. Summarization
Compress long conversation histories:
- Keep system message
- Keep most recent messages (min 4)
- Summarize older messages into key points

#### 2. Compression
Remove redundancy:
- Remove duplicate system messages
- Remove very short messages (< 10 chars)
- Merge consecutive same-role messages

#### 3. Retrieval Pruning
Only include relevant context:
- Prune objection history if not relevant
- Prune sentiment if not relevant
- Filter message history by topic relevance

#### 4. Prompt Caching
Reuse common prompt prefixes:
- Cache by (tone, scenario) combination
- 9 cached combinations (3 tones × 3 scenarios)

### Token Budget
- System prompt: 30% of budget
- Conversation: 70% of budget
- Default max: 3000 tokens

### Functions
- `estimate_tokens(text)` — Estimate token count
- `summarize_conversation(messages, max_tokens)` — Compress history
- `compress_messages(messages)` — Remove redundancy
- `prune_retrieval_context(context, topics)` — Filter relevance
- `optimize_prompt(system, messages, context, max_tokens)` — Full optimization
