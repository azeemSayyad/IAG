# Phase 50 — Global Scale + Multi-Region

## Overview

Phase 50 transforms Launchpad from a single-region deployment into a globally distributed, enterprise-grade SaaS platform with multi-region redundancy, automatic failover, and edge-optimized content delivery.

## Step 50.1 — Multi-Region Deployment

### What Was Built

- **3 AWS regions**: us-east-1 (primary), eu-west-1, ap-southeast-1
- **Per-region resources**: ECR, ECS cluster, ECS service, ALB, CloudWatch logs
- **Shared IAM roles**: ECS execution role, ECS task role
- **ACM certificate**: Wildcard certificate covering all regional domains

### Files

| File | Purpose |
|------|---------|
| `infrastructure/aws/multi-region.tf` | Regional ECS, ECR, ALB, IAM, S3, security groups |
| `infrastructure/aws/providers.tf` | AWS provider aliases for each region |

### Configuration

```hcl
# regions variable defines per-region settings:
"us-east-1" = {
  is_primary    = true
  desired_count = 2
  cpu           = "512"
  memory        = "1024"
}
"eu-west-1" = {
  is_primary    = false
  desired_count = 2
  cpu           = "512"
  memory        = "1024"
}
"ap-southeast-1" = {
  is_primary    = false
  desired_count = 1
  cpu           = "512"
  memory        = "1024"
}
```

### Deployment

```bash
./scripts/deploy-multi-region.sh production
```

## Step 50.2 — Global Database Replication

### What Was Built

- **Aurora Global Database**: Primary cluster in us-east-1 with read replicas in eu-west-1 and ap-southeast-1
- **Cross-region replication lag**: < 1 second typical
- **Backtrack**: 72-hour point-in-time recovery on primary
- **Automated failover**: RPO < 1 second, RTO < 1 minute
- **CloudWatch alarms**: Replication lag monitoring per secondary region

### Files

| File | Purpose |
|------|---------|
| `infrastructure/aws/aurora-global.tf` | Aurora Global Cluster, primary + secondary clusters, subnet groups, security groups, replication lag alarms |

### Database Architecture

```
┌─────────────────────────────────────────────────────────┐
│                 Aurora Global Cluster                    │
│                                                         │
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐    │
│  │ us-east-1   │  │ eu-west-1   │  │ap-southeast-1│   │
│  │             │  │             │  │             │    │
│  │  Writer ────┼──┼──► Reader   │  │             │    │
│  │  Reader     │  │             │  │  Reader     │    │
│  │             │  │             │  │             │    │
│  │ Backtrack   │  │ Replication │  │ Replication │    │
│  │ 72 hours    │  │ Lag < 1s    │  │ Lag < 1s    │    │
│  └─────────────┘  └─────────────┘  └─────────────┘    │
└─────────────────────────────────────────────────────────┘
```

### Failover Process

1. **Automatic**: Aurora detects primary failure
2. **Promotion**: Secondary cluster promoted to standalone writer
3. **DNS Update**: Route 53 health checks detect failure, reroute traffic
4. **Application**: ECS services in DR region connect to promoted cluster

### Manual Failover

```bash
./scripts/disaster-recovery.sh failover eu-west-1
```

## Step 50.3 — Geo Routing

### What Was Built

- **Route 53 latency-based routing**: Users connect to the closest healthy region
- **Health checks**: HTTPS health checks per region (10s interval, 3 failure threshold)
- **Failover routing**: Automatic failover if primary region is unhealthy
- **Direct regional access**: api-us/api-eu/api-ap.launchpad.com for debugging
- **WebSocket routing**: ws.launchpad.com with same latency-based routing

### Files

| File | Purpose |
|------|---------|
| `infrastructure/aws/route53-geo.tf` | Health checks, latency-based records, failover records, direct regional access |

### DNS Architecture

```
api.launchpad.com
  ├─ us-east-1    (latency: ~20ms from US East)
  ├─ eu-west-1    (latency: ~30ms from Europe)
  └─ ap-southeast-1 (latency: ~40ms from Asia)

ws.launchpad.com
  ├─ us-east-1    (latency-based)
  ├─ eu-west-1    (latency-based)
  └─ ap-southeast-1 (latency-based)

app.launchpad.com
  └─ CloudFront   (global edge locations)

api-failover.launchpad.com
  ├─ PRIMARY: us-east-1
  └─ SECONDARY: eu-west-1 (automatic failover)
```

### Health Check Configuration

```hcl
# Each region has:
resource "aws_route53_health_check" "primary_api" {
  fqdn              = "api-us.launchpad.com"
  port              = 443
  type              = "HTTPS"
  resource_path     = "/health"
  failure_threshold = 3
  request_interval  = 10
  measure_latency   = true
}
```

## Step 50.4 — Edge CDN

### What Was Built

- **CloudFront distribution**: Global CDN for frontend static assets
- **S3 origin**: Frontend assets stored in S3 with Origin Access Control
- **API passthrough**: /api/* requests forwarded to regional ALB with failover
- **WebSocket passthrough**: /socket.io/* forwarded without caching
- **SPA routing**: CloudFront function rewrites all non-file requests to index.html
- **Security headers**: HSTS, X-Frame-Options, CSP, XSS protection
- **WAF integration**: Rate limiting, SQL injection, common attack patterns
- **HTTP/3 support**: Enabled for maximum performance
- **S3 cross-region replication**: Frontend assets replicated to EU region

### Files

| File | Purpose |
|------|---------|
| `infrastructure/aws/cloudfront.tf` | CloudFront distribution, S3 bucket, OAC, cache policies, WAF, response headers, SPA rewrite function, S3 replication |

### Cache Strategy

| Path | TTL | Origin |
|------|-----|--------|
| `/` (default) | 24 hours | S3 |
| `/api/*` | 0 (no cache) | ALB (primary → EU failover) |
| `/socket.io/*` | 0 (no cache) | ALB |
| `/_next/static/*` | 1 year | S3 |

### Origin Failover

```
/api/* request
  ├─ Primary: us-east-1 ALB
  │   └─ 5xx error? → failover
  └─ Secondary: eu-west-1 ALB
```

## Step 50.5 — Disaster Recovery

### What Was Built

- **S3 cross-region replication**: Backup buckets replicated from us-east-1 to eu-west-1
- **Aurora Global Database**: Automatic failover with < 1 second RPO
- **ElastiCache Redis**: Multi-AZ with automatic failover per region
- **CloudWatch alarms**: CPU, connections, 5xx errors trigger DR alerts
- **SNS notifications**: Email alerts for DR events
- **Automated snapshots**: Daily Aurora snapshots with cross-region copy

### Files

| File | Purpose |
|------|---------|
| `infrastructure/aws/disaster-recovery.tf` | S3 replication, Aurora snapshots, CloudWatch alarms, SNS, ElastiCache per region |
| `scripts/disaster-recovery.sh` | DR operations: status, failover, failback, test, backup |

### DR Metrics

| Metric | Target | How |
|--------|--------|-----|
| RPO (Recovery Point Objective) | < 1 second | Aurora Global Database synchronous replication |
| RTO (Recovery Time Objective) | < 15 minutes | Automatic failover + Route 53 health checks |
| Backup Retention | 7 days | Aurora automated backups |
| Snapshot Retention | 365 days | S3 lifecycle (30d → Glacier, 365d → expire) |

### DR Procedures

#### Automatic Failover (Route 53)

1. Primary region health check fails (3 consecutive failures)
2. Route 53 removes primary from latency-based routing
3. Traffic automatically routes to nearest healthy region
4. Aurora promotes secondary cluster to standalone writer
5. SNS alert sent to ops team

#### Manual Failover

```bash
# Check current status
./scripts/disaster-recovery.sh status

# Failover to EU region
./scripts/disaster-recovery.sh failover eu-west-1

# After primary is recovered, failback
./scripts/disaster-recovery.sh failback
```

#### DR Testing

```bash
# Non-destructive test
./scripts/disaster-recovery.sh test

# Manual backup
./scripts/disaster-recovery.sh backup
```

## Deployment

### Prerequisites

- AWS CLI configured with appropriate credentials
- Terraform >= 1.5.0
- Docker installed
- VPCs created in all 3 regions
- Route 53 hosted zone for launchpad.com

### Deploy Everything

```bash
# Deploy infrastructure to all regions
./scripts/deploy-multi-region.sh production

# Verify health
./scripts/disaster-recovery.sh status

# Run DR test
./scripts/disaster-recovery.sh test
```

### Deploy Individual Components

```bash
# Infrastructure only
cd infrastructure/aws
terraform apply -var="environment=production"

# Frontend only
cd apps/frontend && npm run build
aws s3 sync out s3://launchpad-frontend-production

# Invalidate CloudFront
aws cloudfront create-invalidation --distribution-id <ID> --paths "/*"
```

## Rollback

To rollback to single-region deployment:

1. Update Route 53 to point only to primary region
2. Scale down ECS in secondary regions
3. Remove secondary Aurora clusters
4. Update Terraform state

```bash
# Scale down secondary regions
aws ecs update-service --cluster launchpad-cluster-eu --service launchpad-backend-service-eu --desired-count 0 --region eu-west-1
aws ecs update-service --cluster launchpad-cluster-ap --service launchpad-backend-service-ap --desired-count 0 --region ap-southeast-1
```
