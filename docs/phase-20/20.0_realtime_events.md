## STEP 20.2 — Socket Authentication

**File:** `realtime/websocket.py` (connect handler)

JWT-based authentication for WebSocket connections.

### Authentication Flow
```
Client → Connect with { token: "jwt_token" }
Server → Validate JWT token
Server → Extract user_id, tenant_id, role
Server → Join appropriate rooms
Server → Send "connected" confirmation
```

### Token Validation
- Decode JWT access token
- Verify token type is "access"
- Check user exists and is not deleted
- Extract tenant_id and role

### Error Handling
- Missing token → Connection refused
- Invalid token → Connection refused
- Expired token → Connection refused
- User not found → Connection refused

## STEP 20.3 — Room Architecture

### Room Types

| Room | Pattern | Purpose |
|------|---------|---------|
| Tenant Room | `tenant:{tenant_id}` | All users in tenant |
| Role Room | `tenant:{tenant_id}:{role}` | Users with specific role |
| Agent Room | `agent:{user_id}` | Specific agent |

### Room Membership
- On connect: Join tenant room + role room
- If agent: Also join agent room
- On disconnect: Leave all rooms

### Messaging to Rooms
```python
# Send to all users in tenant
await emit_to_tenant(tenant_id, "event", data)

# Send to specific role
await emit_to_role(tenant_id, "tenant_admin", "event", data)

# Send to specific agent
await emit_to_agent(agent_id, "event", data)

# Send to specific user
await emit_to_user(user_id, "event", data)
```

## STEP 20.4 — Pub/Sub System

**File:** `realtime/pubsub.py`

Redis Pub/Sub for cross-instance synchronization.

### Channels

| Channel | Purpose |
|---------|---------|
| `realtime:notifications` | General notifications |
| `realtime:bookings` | Booking events |
| `realtime:agents` | Agent events |
| `realtime:system` | System events |

### Functions
- `publish_notification(tenant_id, data)` — Publish notification
- `publish_booking_event(tenant_id, event_type, data)` — Publish booking event
- `publish_agent_event(tenant_id, agent_id, event_type, data)` — Publish agent event
- `publish_system_event(event_type, data)` — Publish system event

### Message Format
```json
{
    "tenant_id": "...",
    "event_type": "...",
    "data": {...},
    "timestamp": "2026-01-15T10:30:00Z"
}
```

## STEP 20.5 — Event Types

### Booking Events
| Event | Trigger | Recipients |
|-------|---------|------------|
| `new_booking` | Appointment created | Tenant admins, assigned agent |
| `booking_cancelled` | Appointment cancelled | Tenant admins, assigned agent |
| `booking_rescheduled` | Appointment rescheduled | Tenant admins, assigned agent |
| `booking_reassigned` | Agent reassigned | Tenant admins, old agent, new agent |
| `booking_reminder` | Reminder sent | Assigned agent |

### Lead Events
| Event | Trigger | Recipients |
|-------|---------|------------|
| `lead_created` | New lead imported | Tenant admins, managers |
| `lead_updated` | Lead data changed | Tenant admins |
| `lead_replied` | Customer replied | Tenant admins |
| `lead_qualified` | Lead qualified | Tenant admins |
| `lead_scored` | Score calculated | Tenant admins |
| `lead_status_changed` | Status changed | Tenant admins, managers |

### AI Events
| Event | Trigger | Recipients |
|-------|---------|------------|
| `ai_response_generated` | Response generated | Tenant admins |
| `ai_intent_detected` | Intent classified | Tenant admins |
| `ai_objection_handled` | Objection addressed | Tenant admins |
| `ai_outreach_sent` | Outreach message sent | Tenant admins |

### Conversation Events
| Event | Trigger | Recipients |
|-------|---------|------------|
| `conversation_state_changed` | State transition | Tenant admins |
| `conversation_started` | New conversation | Tenant admins |
| `conversation_ended` | Conversation closed | Tenant admins |

### Agent Events
| Event | Trigger | Recipients |
|-------|---------|------------|
| `agent_status_change` | Agent online/offline | Tenant admins |
| `agent_utilization_alert` | Low/high utilization | Tenant admins, managers |

### System Events
| Event | Trigger | Recipients |
|-------|---------|------------|
| `system_alert` | System issue | All tenant users |

| `queue_alert` | Queue issue | Tenant admins |

## API Endpoints

### REST Endpoints
```
GET  /api/v1/realtime/online     — Get online users
GET  /api/v1/realtime/status     — Get connection status
POST /api/v1/realtime/notify     — Send notification
```

### WebSocket Events
```
Connect: ws://api.launchpad.com/socket.io
Auth: { token: "jwt_access_token" }

Events emitted:
- connected (on connect)
- notification (various types)
- room_joined (on room join)
- room_left (on room leave)
```

## Frontend Integration

    auth: { token: accessToken }
});

// Listen for notifications

    console.log('Notification:', data.type, data.message);
});

// Listen for specific events
socket.on('new_booking', (data) => {
    updateCalendar(data);
});
